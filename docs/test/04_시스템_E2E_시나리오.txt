================================================================================
 04. 시스템(E2E) 테스트 시나리오
================================================================================
 대상: 브라우저에서 사용자가 겪는 전체 흐름 / 도구: 수동 수행 -> Playwright 자동화
 환경: Vercel Preview 또는 로컬(npm run dev) + 테스트용 Supabase 프로젝트
 계정 준비: 일반 회원 3명(HOST/A/B), 관리자 1명, 정지 회원 1명
 기본 확인 기기: PC Chrome, 모바일 Safari(iOS), 모바일 Chrome(Android)
 기록 방식: 각 단계 결과를 O/X 로 표시하고 X 는 08번 결함 보고서에 등록

--------------------------------------------------------------------------------
 E2E-001 [상] 신규 가입 -> 첫 매칭 방 만들기
--------------------------------------------------------------------------------
 사전: 비로그인 상태
 1. 메인 페이지 접속 -> 히어로/소개/부천 코트 링크/CTA 가 깨지지 않고 표시
 2. [회원가입] -> 약관/개인정보 동의 체크 -> 필수 미체크 시 가입 불가 확인
 3. 이메일/비밀번호/닉네임 입력 -> 닉네임 1자·21자 오류, 이메일 형식 오류 메시지 확인
 4. 본인인증 단계: (A) PortOne 연동 환경: 인증 완료 후 진행
                   (B) 임시가입 환경(ALLOW_UNVERIFIED_SIGNUP=true): "본인인증 없이 가입" 버튼 표시
 5. 가입 완료 -> 로그인 상태가 되고 헤더에 프로필/알림이 보임
 6. [매칭 만들기] -> 테니스장 검색 후 선택 -> 날짜 기본값이 "오늘(한국 시간)" 인지 확인
 7. 인기 시간 칩이 있으면 클릭 -> 날짜/시간이 채워지는지 확인 (데이터 없으면 칩 영역 숨김)
 8. 과거 시간 입력 후 생성 -> 거부 메시지 확인 / 미래 시간으로 생성 성공
 9. 생성된 방 상세 화면에서 내가 방장으로 표시, 목록에도 노출
 기대: 모든 단계 오류 없이 진행, 새로고침해도 로그인 유지

--------------------------------------------------------------------------------
 E2E-002 [상] 참가 신청 -> 수락 -> 결제 확인 -> 완료 -> 평가
--------------------------------------------------------------------------------
 1. A 로 로그인 -> 방 상세 -> [참가 신청] -> 성공, 버튼이 "신청 완료"로 변경
 2. 같은 방에 다시 신청 불가 확인, HOST 는 신청 버튼 없음
 3. HOST 로그인 -> 신청자 목록에서 A [수락] -> A 에게 알림(인앱) 도착
 4. 참가비가 있는 방: HOST 가 [입금 확인] -> A 알림 도착, 다시 누르면 해제
 5. A, B 도 같은 방에 신청, B 는 [거절] -> B 에게 거절 알림
 6. 방 채팅: HOST/A 메시지 주고받기, B(거절) 와 제3자는 채팅 불가
 7. 경기 후 HOST [경기 완료] -> 상태 "완료"
 8. HOST/A 상호 평가 화면: 대상 목록에 본인/거절자 제외, 매너 1~5/NTRP 1.0~7.0 입력
 9. 제출 후 상대 프로필의 매너 온도/평가 횟수 변화 확인, 재제출 시 덮어쓰기
 기대: 단계별 상태 변화가 즉시 화면에 반영, 권한 없는 사용자는 버튼 자체가 보이지 않거나 거부 메시지

--------------------------------------------------------------------------------
 E2E-003 [상] 레벨/매너 제한 방 참가
--------------------------------------------------------------------------------
 1. HOST 가 "NTRP 3.0 ~ 4.0" 방 생성, 최소 매너온도 37 설정
 2. 평가 3회 미만 회원 -> 신청 시 "NTRP 검증(평가 3회 이상)" 안내
 3. 표시 레벨이 범위 밖인 회원 -> 레벨 안내 메시지(현재 내 레벨 포함)
 4. 매너 온도가 기준 미만인 회원 -> 매너 기준 안내 메시지
 5. 조건에 맞는 회원 -> 신청 성공
 기대: 메시지가 구체적이며 줄바꿈이 화면에서 정상 표시

--------------------------------------------------------------------------------
 E2E-004 [상] 대회: 개설 -> 신청 -> 대진표 -> 결과 -> 트로피
--------------------------------------------------------------------------------
 1. 관리자: [대회 개설] -> 단식 대회 생성(NTRP 범위, 정원, 매너 기준)
 2. 자격 미달 회원이 신청 -> 사유 메시지 / 자격 충족 회원 4명 신청 성공
 3. 관리자: 대진표 생성 -> 4강 2경기 + 결승 + 3·4위전 총 4경기 표시
 4. 각 경기 승자 입력 -> 다음 라운드 자동 진출, 잘못된 선수 지정 불가
 5. 결승/3·4위전 입력 -> 대회 종료, 1~3위 확정
 6. 우승자 프로필: 금 트로피, "첫 우승" 칭호 표시, 기록실에 결과 노출
 7. 관리자: 대진표 초기화 -> 확인 창 후 초기화, 작업 기록 탭에 기록 남음
 8. 복식 대회: 팀 구성(파트너 초대) -> 파트너 수락 -> 평균 NTRP 상한 초과 팀은 거부
 9. 참가자 3명/5명 대회에서 부전승이 올바르게 처리되는지 확인
 기대: 대진표 시각화가 모바일에서도 가로 스크롤로 확인 가능

--------------------------------------------------------------------------------
 E2E-005 [상] 관리자 일상 업무
--------------------------------------------------------------------------------
 1. 일반 회원이 /admin 접근 -> "관리자만 접근" 안내 또는 로그인 이동
 2. 관리자 로그인 -> 대시보드: 오늘/누적 방문자, 일별 방문/가입 차트, 시간대 차트 표시
 3. "지역·코트별 주간 매칭 수 추이", "요일·시간대 히트맵"이 표시되고 탭/모드 전환 동작
 4. 회원 관리: 닉네임/이메일/ID 검색, 필터, 상세 보기 -> 임시가입 회원에 "미인증" 표시
 5. 회원 정지(사유 입력) -> 해당 회원 로그인 후 일반 기능 거부 확인 -> 정지 해제
 6. 회원 CSV 내보내기 -> 파일 열어 한글 깨짐 여부, 수식 인젝션 처리 확인
 7. 작업 기록: 방금 한 정지/해제/내보내기가 시간, 관리자, 대상과 함께 기록, 필터/검색 동작
 8. 관리자 화면 자체의 방문은 방문 통계에 잡히지 않는지 확인
 기대: 모든 관리자 동작이 작업 기록에 남고 일반 회원 화면에는 영향 없음

--------------------------------------------------------------------------------
 E2E-006 [상] 서비스 점검 모드
--------------------------------------------------------------------------------
 1. 관리자: 점검 모드 화면 -> 문구와 종료 예정 시각 입력 -> [켜기] -> 확인 창 -> 켜짐 표시
 2. 일반 회원(다른 브라우저/시크릿 창): 새로고침 -> 마스코트와 점검 안내 화면만 표시, 문구/종료시각 표시
 3. 이미 열려 있던 일반 회원 탭: 최대 1분 안에 점검 화면으로 전환
 4. 점검 중 일반 회원: /login, /terms, /privacy 접근 가능, 그 외 경로는 점검 화면
 5. 점검 중 일반 회원이 개발자도구 등으로 방 생성 등 서버 동작 시도 -> "서비스 점검 중" 거부
 6. 점검 중 신규 가입 -> 거부 (관리자 초대코드 입력 시에만 통과)
 7. 관리자는 점검 중에도 모든 화면 정상 이용, 상단에 "점검 모드 ON" 띠 표시
 8. 관리자: [끄기] -> 일반 회원 화면이 최대 1분 내 정상 복귀
 9. 종료 예정 시각을 2~3분 뒤로 설정해 켜 둔 뒤 시각 경과 -> 자동 해제 확인
 10. 켜기/끄기/문구 수정이 작업 기록에 각각 남음
 기대: 점검 중에도 관리자가 로그인해 해제할 수 있어야 함 (잠김 방지)

--------------------------------------------------------------------------------
 E2E-007 [중] 알림 / 코트 빈자리 / 프로필
--------------------------------------------------------------------------------
 1. 알림함: 수락/거절/입금 확인 알림이 쌓이고 읽음 처리, 모두 읽음, 안 읽은 수 배지 갱신
 2. 푸시 권한 허용 -> 기기 토큰 등록 -> 수락 시 실제 푸시 수신 (모바일)
 3. 부천 코트 빈자리 알림 구독/해제, 구독 목록 표시
 4. 프로필 수정(닉네임, 구력, 성별 등) 저장 -> 새로고침 후 유지
 5. 기록실/전적 화면: 내 경기 수, 승패, 트로피 진열장 표시
 6. 회원 탈퇴 -> 로그인 불가, 재가입 가능 여부는 정책대로(정지 회원은 재가입 불가)

--------------------------------------------------------------------------------
 E2E-008 [중] 정지 회원 시나리오
--------------------------------------------------------------------------------
 1. 정지 회원 로그인 -> 알림 조회, 프로필 조회, 탈퇴만 가능
 2. 방 생성/참가/채팅/댓글/평가 -> "이용이 제한된 계정입니다." 거부
 3. 정지 회원이 탈퇴 후 같은 이메일(임시가입)/같은 인증정보로 재가입 시도 -> 거부

--------------------------------------------------------------------------------
 E2E-009 [중] 공개 페이지 / 마케팅 유입
--------------------------------------------------------------------------------
 1. 비로그인 상태로 메인, 매칭 목록, 대회 목록, 약관, 개인정보처리방침 접근 가능
 2. 메인의 부천 예약 링크 클릭 -> reserv.bucheon.go.kr 로 이동(새 창/정상 URL)
 3. 비로그인으로 보호 화면(마이페이지, 방 만들기) 접근 -> 로그인 화면으로 이동
 4. 방문 집계: 비로그인 방문이 대시보드 방문자 수에 반영(관리자/봇/API 경로 제외)

--------------------------------------------------------------------------------
 E2E-010 [하] 공통 UI
--------------------------------------------------------------------------------
 1. 클릭 가능한 요소(버튼/링크/칩/카드)에 마우스 올리면 포인터 변경 + 색 변화
 2. 로딩 화면 테니스 라켓 애니메이션이 자연스럽게 반복되고 마스코트 머리띠 겹침 없음
 3. 모바일(폭 360px)에서 가로 스크롤이 생기지 않음(표/히트맵/대진표 제외)

--------------------------------------------------------------------------------
 E2E 자동화 우선순위 (Playwright)
--------------------------------------------------------------------------------
 1순위 E2E-001 (가입 -> 방 생성)   2순위 E2E-002 (신청 -> 수락)   3순위 E2E-006 (점검 모드)
 인증은 Supabase 테스트 계정으로 로그인한 storageState 를 재사용해 속도를 확보한다.
