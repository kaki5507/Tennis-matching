================================================================================
 05. 보안 테스트 체크리스트
================================================================================
 표기: [필수] = 배포 전 반드시 통과, [권장] = 가능하면 통과
 수행 방법: 통합 테스트(모킹된 토큰) + 브라우저 개발자도구/curl 수동 확인
 핵심 원칙: Next.js 서버 액션은 "공개 API" 이다. 화면에서 숨긴 버튼은 보안이 아니다.
            서버가 토큰으로 본인/권한을 직접 확인하는지가 전부다.

--------------------------------------------------------------------------------
 A. 인증 / 인가
--------------------------------------------------------------------------------
 SEC-001 [필수] 토큰 없이 모든 서버 액션 호출 -> 전부 거부(공개 조회 액션 제외: getPopularTimes,
                 목록/상세 조회 등 의도된 공개 기능만 허용)
 SEC-002 [필수] 다른 사용자의 id 를 인자/바디로 넣어도 항상 토큰 소유자로 동작 (userId, hostId,
                 evaluatorId, adminId 등 클라이언트 전달 값 불신)
 SEC-003 [필수] 일반 회원 토큰으로 모든 admin 액션 호출 -> 거부 (IT-ADM-001 목록 전체)
 SEC-004 [필수] 정지/탈퇴 계정 토큰으로 일반 액션 -> 거부 (allowBanned 허용 목록만 예외)
 SEC-005 [필수] 방장 전용 액션(수락/거절/마감/완료/입금확인)을 제3자·참가자가 호출 -> 거부
 SEC-006 [필수] 본인 데이터 전용 액션(알림, 프로필, 코트알림, 신청 취소)을 타인 id 로 호출 -> 거부
 SEC-007 [필수] 위조/만료 JWT, 다른 프로젝트에서 발급한 JWT -> 거부
 SEC-008 [권장] 서버 액션 호출 시 인자 순서가 바뀌어도(accessToken 이 첫 인자) 타입 오류/거부로
                 끝나고 임의 사용자로 동작하지 않는지 확인

--------------------------------------------------------------------------------
 B. 관리자 권한 / 가입
--------------------------------------------------------------------------------
 SEC-010 [필수] 관리자 초대코드(ADMIN_SIGNUP_CODE) 오답은 오류 없이 일반 회원 가입(코드 존재 비노출),
                 미설정 시 어떤 값으로도 ADMIN 불가
 SEC-011 [필수] role 을 바꾸는 경로(프로필 수정, 가입 바디의 role 필드 등)가 없고, 있다면 무시됨
 SEC-012 [권장] 관리자 초대코드 무차별 대입 방어(속도 제한) - 현재 없음, 위험 인지 필요 (F-12)
 SEC-013 [필수] 임시 가입 스위치: PORTONE_API_SECRET 설정 시 ALLOW_UNVERIFIED_SIGNUP 이 켜져 있어도
                 임시가입 거부, 운영에서 스위치 미설정이면 거부
 SEC-014 [권장] 임시 가입자는 다른 이메일로 정지를 회피할 수 있음(알려진 한계) - PG 계약 전까지
                 모니터링(관리자 화면의 "미인증" 표시 활용)

--------------------------------------------------------------------------------
 C. 입력 검증 / 인젝션
--------------------------------------------------------------------------------
 SEC-020 [필수] 모든 문자열 입력에 길이 상한 (설명 2000자, 문구 300자, 닉네임 20자 등)
 SEC-021 [필수] 숫자/날짜/시간 범위 검증 (참가비, 매너온도, NTRP, 날짜 형식, 과거 시각)
 SEC-022 [필수] 원시 SQL($queryRaw)은 Prisma.sql 템플릿 변수만 사용 (문자열 이어붙이기 금지)
                 -> 코드 검색: $queryRawUnsafe, "+" 로 SQL 조립이 없는지 확인
 SEC-023 [필수] 사용자 입력이 화면에 출력될 때 XSS 방지: 닉네임/설명/채팅/댓글에
                 <script>alert(1)</script>, <img src=x onerror=...> 입력 -> 텍스트로만 표시
                 (dangerouslySetInnerHTML 사용 여부 코드 검색)
 SEC-024 [필수] CSV 내보내기 수식 인젝션: 닉네임이 =HYPERLINK(...), +cmd, -1+1, @SUM 로 시작할 때
                 셀이 수식으로 실행되지 않도록 처리(앞에 ' 추가 등)
 SEC-025 [권장] 검색어/필터 값에 특수문자('%_\"\\) 입력 시 오류 없이 동작
 SEC-026 [권장] 점검 모드 안내 문구에 HTML 입력 -> 텍스트로 표시 (whitespace-pre-line, HTML 해석 없음)

--------------------------------------------------------------------------------
 D. 개인정보 / 비밀값
--------------------------------------------------------------------------------
 SEC-030 [필수] 본인인증 식별값(ciDi)이 클라이언트 응답/화면/CSV 에 노출되지 않음 (identityVerified 만)
 SEC-031 [필수] 환경변수 노출 점검: NEXT_PUBLIC_ 접두어가 붙은 값은 브라우저에 공개됨
                 -> 비밀키(DB URL, PORTONE_API_SECRET, ADMIN_SIGNUP_CODE, CRON_SECRET,
                    FIREBASE 서버 키, Supabase service role 키)에 NEXT_PUBLIC_ 이 없는지 확인
 SEC-032 [필수] 소스 저장소/문서/대화에 노출된 토큰·키 폐기 및 재발급
                 (GitHub PAT 등 과거 노출분) - 폐기 완료 여부를 체크
 SEC-033 [필수] 빌드 번들에 비밀값이 포함되지 않음: 배포 후 브라우저 개발자도구 Sources 에서
                 서버 전용 키 문자열 검색 -> 없어야 함
 SEC-034 [필수] 관리자 CSV/회원 상세는 접근 시 작업 기록이 남아 사후 추적 가능 (USER_EXPORT, USER_VIEW)
 SEC-035 [권장] 에러 응답에 스택트레이스/SQL/내부 경로 미노출 (사용자에게는 일반 문구)
 SEC-036 [권장] 개인정보 보관/파기 정책: 탈퇴 회원 데이터 처리 기준 문서화(개인정보처리방침과 일치)

--------------------------------------------------------------------------------
 E. API / 인프라
--------------------------------------------------------------------------------
 SEC-040 [필수] 크론 엔드포인트: Authorization 헤더 검증 (F-09 수정 완료: CRON_SECRET 미설정 시에도 401)
                 -> 배포 환경에 CRON_SECRET 설정 확인 + 수정 후 미설정 시 401
 SEC-041 [권장] /api/track 남용(대량 호출) 시 DB 부하: 속도 제한 또는 크기 제한 검토
 SEC-042 [필수] /api/maintenance 는 공개 필드만 반환, 캐시 비활성
 SEC-043 [필수] HTTPS 강제, 쿠키 설정(Secure, SameSite) - Supabase 기본 동작 확인
 SEC-044 [권장] 의존성 취약점: npm audit 결과 high/critical 0건 또는 위험 수용 사유 기록
 SEC-045 [권장] CORS/Origin: 서버 액션은 같은 Origin 만 허용(Next.js 기본) 확인
 SEC-046 [필수] Supabase RLS(행 수준 보안): 클라이언트에서 anon 키로 직접 테이블 접근 가능한지 확인
                 -> RLS 비활성이면 Prisma 서버 경유 보안이 무의미해질 수 있음. 테이블별 정책 점검
 SEC-047 [권장] Supabase 이메일 인증 설정과 가입 흐름 일치 확인(인증 켜면 세션 없음 문제 - F-10)

--------------------------------------------------------------------------------
 F. 점검 모드 관련
--------------------------------------------------------------------------------
 SEC-050 [필수] 점검 모드 화면 차단은 UI 수준이므로, 서버 액션 차단(requireUser)이 실제로 동작하는지
                 확인 (IT-MNT-008)
 SEC-051 [권장] 점검 중 공개 조회 액션(대회 목록 등)은 서버에서 막지 않음(알려진 한계) - 허용 여부 결정
 SEC-052 [필수] 점검 모드 DB 오류 시 fail-open 이므로, 점검이 켜졌는데 DB 장애로 해제된 것처럼 보이는
                 상황은 장애 대응 문서에 기록

              실제 엑셀 열기 확인은 E2E-005 에서 수행
 SEC-031 관련: 코드에서 쓰는 NEXT_PUBLIC_ 값은 Firebase 웹 설정, PortOne 스토어/채널 키,
              Supabase URL/ANON 키, 카카오맵 앱 키 뿐이며 모두 공개되어도 되는 종류 -> 통과(정적)
              (Supabase service role 키는 코드에서 사용하지 않음. 앞으로도 NEXT_PUBLIC_ 금지)

 남은 항목은 실행 테스트가 필요하며, 아직 수행되지 않았음.
