================================================================================
 03. 통합 테스트 명세서
================================================================================
 대상: 서버 액션(app/actions/*) + Prisma + 테스트 DB
 방식: Supabase 토큰 검증(supabase.auth.getUser)만 모킹하고 나머지는 실제 DB 사용 권장
       (SQL/마이그레이션 오류까지 잡기 위함). 푸시 발송(sendPushToUser)은 모킹.

[공통 준비 - 픽스처]
 U_HOST   : 일반 회원(방장 역할)          U_A, U_B : 일반 회원(참가자 역할)
 U_ADMIN  : role=ADMIN                     U_BAN    : isBanned=true
 U_DEL    : deletedAt 설정(탈퇴)           U_NOPROF : 토큰은 유효하나 users 행 없음
 COURT_1  : 부천 소재 코트 (주소 "경기도 부천시 ...")
 TOKEN_<이름> : getUser 모킹이 해당 사용자 id 를 돌려주는 가짜 토큰, 잘못된 토큰은 오류 반환
 각 테스트는 트랜잭션 롤백 또는 truncate 로 격리한다.

--------------------------------------------------------------------------------
 A. 인증 문지기 (lib/serverAuth.ts, lib/adminAuth.ts) - 모든 액션의 공통 전제
--------------------------------------------------------------------------------
 IT-AUTH-001 [상] 토큰 null/빈 문자열 -> "로그인이 필요합니다."
 IT-AUTH-002 [상] 만료/위조 토큰 -> "로그인 정보를 확인할 수 없습니다..."
 IT-AUTH-003 [상] 유효 토큰 + users 행 없음(U_NOPROF) -> "가입이 완료되지 않은 계정입니다."
 IT-AUTH-004 [상] 탈퇴 회원(U_DEL) -> "탈퇴한 계정입니다." (allowBanned 여도 거부)
 IT-AUTH-005 [상] 정지 회원(U_BAN) -> 일반 액션 거부 "이용이 제한된 계정입니다."
 IT-AUTH-006 [상] 정지 회원 + allowBanned 액션(알림 조회, 탈퇴, 프로필 조회, 코트알림 해제 등)
                  -> 허용
 IT-AUTH-007 [상] requireAdmin: ADMIN 통과 / 일반 회원 거부 / 정지된 ADMIN 거부 / 탈퇴 ADMIN 거부
 IT-AUTH-008 [상] 점검 모드 ON 상태에서 일반 회원의 requireUser -> "서비스 점검 중입니다..." 거부,
                  ADMIN 은 통과 (IT-MNT 와 연계)

 B. 회원 가입 / 인증 (auth.ts, verification.ts, portone.ts)
--------------------------------------------------------------------------------

 IT-SGN-002 [상] PORTONE_API_SECRET 설정 + 유효한 인증ID -> 가입 성공, ciDi 가 실제 값으로 저장
 IT-SGN-003 [상] PORTONE_API_SECRET 설정 + 인증ID 없음/무효 -> 거부 (임시가입 스위치 무시)
 IT-SGN-004 [상] PORTONE 없음 + ALLOW_UNVERIFIED_SIGNUP="true" + 인증 없이 -> 가입 성공,
                 ciDi 가 "unverified_" 로 시작, 관리자 회원목록에서 identityVerified=false
 IT-SGN-005 [상] PORTONE 없음 + production + 스위치 미설정 -> 인증 없이 가입 거부
 IT-SGN-006 [상] 같은 이메일로 임시가입 2회 -> 두 번째 "이미 가입된 본인인증 정보입니다." 거부
 IT-SGN-007 [상] 정지(BannedIdentity 등록)된 사용자의 같은 이메일로 재가입 -> 거부
 IT-SGN-008 [중] 같은 CI/DI(실인증)로 다른 이메일 재가입 -> 중복 가입 거부
 IT-SGN-009 [상] 관리자 초대코드: 틀린 코드 -> 오류 없이 일반 회원(role=USER)으로 가입(코드 존재 노출 방지),
                 맞는 코드 -> role=ADMIN (타이밍 안전 비교), ADMIN_SIGNUP_CODE 미설정이면 어떤 코드도 무효
 IT-SGN-010 [상] accessToken 을 함께 보낸 경우 토큰 소유자 id/이메일과 body 가 다르면
                 "가입 계정 정보가 일치하지 않습니다." (토큰 없이 가입하는 경로는 허용 - 발견 사항 F-10)
 IT-SGN-011 [중] 입력 검증: 닉네임 1자/21자 거부(2~20자 통과), 이메일 형식 오류/200자 초과 거부,
                 id 가 UUID 형식이 아니면 "잘못된 요청입니다."
 IT-SGN-012 [상] 점검 모드 ON: 초대코드 없는 가입 거부, 초대코드 있으면 통과
 IT-SGN-013 [중] getSignupMode: 현재 환경변수 조합에 맞는 모드 문자열 반환 (UT-PRT-001 표와 일치)
 IT-SGN-014 [중] devBypassIdentityVerification: unverifiedSignupAllowed() 와 동일하게 동작
                 (PORTONE_API_SECRET 있으면 거부, production 에서 스위치 꺼져 있으면 거부)

 IT-MAT-008 [중] 상세 설명 2001자 거부 / 2000자 통과

 IT-MAT-010 [중] 최소 매너온도 "abc", -1, 100 -> 거부 / "36.5", 36.5, ""(제한없음)=null -> 통과
 IT-MAT-011 [중] 존재하지 않는 courtId -> "테니스장 정보를 찾을 수 없습니다..."
 IT-MAT-012 [상] 정지/탈퇴/미가입 사용자는 방 생성 불가 (IT-AUTH 연계)

 joinMatchRoom
 IT-MAT-020 [상] OPEN 방에 일반 회원 신청 -> MatchParticipant 생성(status=PENDING)
 IT-MAT-021 [상] 방장 본인 신청 -> "방장 본인은 이미 참여 중입니다."
 IT-MAT-022 [상] 같은 방 중복 신청 -> "이미 참여 신청한 방입니다."
 IT-MAT-023 [상] FULL/COMPLETED/CANCELED 방 또는 없는 방 -> "모집이 마감되었거나 존재하지 않는 방입니다."
 IT-MAT-024 [상] 레벨 제한 방("2.0-3.0") + ntrpCount<3 -> "NTRP 검증(평가 3회 이상)..." 거부
 IT-MAT-025 [상] 레벨 제한 방 + 표시 점수(0.5 단위 반올림)가 범위 밖 -> 레벨 안내 메시지 거부
              경계: ntrpScore 2.74 -> 표시 2.5, 2.75 -> 표시 3.0 (Math.round(x*2)/2)
 IT-MAT-026 [상] "누구나"/"ANY" 방은 레벨 검사 생략
 IT-MAT-027 [상] 매너 최소기준 방: 내 매너 < 기준 -> 거부, 같으면 통과(경계)
 IT-MAT-028 [중] 삭제(deletedAt) 방 신청 시 동작 확인 -> 현재 코드는 deletedAt 을 검사하지 않음 (발견 사항 F-05)

 updateParticipantStatus / closeMatch / completeMatchAction
 IT-MAT-030 [상] 방장이 PENDING -> ACCEPTED: 상태 변경 + 신청자에게 알림 발송 1회
 IT-MAT-031 [상] 방장이 REJECTED: 상태 변경 + 거절 알림
 IT-MAT-032 [상] 방장이 아닌 사람(참가자/제3자) -> "방장만 수락/거절할 수 있습니다."
 IT-MAT-033 [상] 이미 같은 상태로 재요청 -> success 이나 알림 중복 발송 없음
 IT-MAT-034 [상] COMPLETED/CANCELED 방에서 상태 변경 시도 -> "이미 끝났거나 취소된 방입니다."
 IT-MAT-035 [중] status 에 'ACCEPTED'/'REJECTED' 외 값 -> "잘못된 요청입니다."
 IT-MAT-036 [상] closeMatch: 방장 -> FULL / 방장 아님 -> 거부
 IT-MAT-037 [중] closeMatch: COMPLETED/CANCELED 방을 FULL 로 되돌리는지 확인 (발견 사항 F-06)
 IT-MAT-038 [상] completeMatchAction: 방장 -> COMPLETED / 이미 완료 -> "이미 완료 처리된 경기입니다."
              / 취소된 방 -> "취소된 경기입니다." / 방장 아님 -> 권한 없음
